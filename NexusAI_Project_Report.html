Project Summary & Contribution

NexusAI is a full-stack, production-grade AI platform that integrates four distinct AI capabilities into a single unified web application. The project demonstrates end-to-end ownership — from LLM orchestration and vector retrieval to a streaming React UI, containerised deployment, and a comprehensive automated test suite.

💬
Memory Chatbot
Conversational AI with persistent memory across sessions using LangGraph's SqliteSaver checkpointing and Groq LLaMA 3.1 8B. Each thread identified by a UUID — history loads automatically.
📄
Document Q&A (RAG)
Upload a PDF, TXT, or DOCX — get answers grounded in your document using Pinecone vector search + HuggingFace local embeddings. Zero hallucination: answers only from retrieved context.
🔍
Research Agent
Searches the web (Tavily API, top 5 results), synthesises a structured summary with citations using Groq LLaMA — fully automated research pipeline.
🧠
Critic Agent
Scores every research output on 4 criteria (Accuracy, Completeness, Clarity, Source Usage — each /10). FAIL triggers automatic query refinement and retry.

System Architecture

NexusAI follows a clean 3-tier architecture: a React frontend communicates with a FastAPI backend via REST and Server-Sent Events (SSE). The backend hosts three independent AI subsystems, each backed by either SQLite (conversations) or Pinecone (vectors).

Key Design Decisions

📡
SSE over WebSockets

Server-Sent Events are one-directional, simpler, and work natively with FastAPI's StreamingResponse. No WebSocket handshake overhead needed for token streaming.

🧠
SqliteSaver (LangGraph Memory)

LangGraph's SqliteSaver handles all chat history automatically per thread_id. No manual DB writes needed — LangGraph loads and saves state around every node execution.

☁️
Pinecone over FAISS

Cloud-hosted vector database survives container restarts, scales to millions of vectors, and requires zero local disk management.

🔄
Stream-then-Save pattern

Messages are only persisted to SQLite after the full stream completes — never mid-stream — preventing partial/corrupted records in the database.

Working / Model Explanation

💬 Feature 1 — Memory Chatbot (LangGraph)

Step 1
User sends a message

POST /api/chat/stream with message + thread_id UUID

Step 2
SqliteSaver loads history

LangGraph reads the complete conversation history for this thread from chatbot.db automatically

Step 3
chat_node → Groq LLaMA 3.1

History + new message sent to the LLM. Response tokens streamed back via SSE

Step 4
Stream completes → State saved

Full response persisted to SQLite via SqliteSaver. Thread ready for next turn.

chatbot/graph.py # Build LangGraph with SqliteSaver checkpointer def build_graph(): graph = StateGraph(ChatState) graph.add_node("chat_node", chat_node) graph.add_edge(START, "chat_node") graph.add_edge("chat_node", END) compiled = graph.compile(checkpointer=checkpointer) # memory ✓ return compiled

📄 Feature 2 — RAG (Retrieval-Augmented Generation)

Ingest
Upload document → chunk → embed → Pinecone

Document split into 500-char chunks (50 overlap). Each chunk embedded using HuggingFace all-MiniLM-L6-v2 (384-dim, local, free). Vectors upserted to Pinecone.

Retrieve
Query → embed → cosine search → top-K chunks

User question is embedded with same model. Pinecone cosine similarity returns top 4 most relevant document chunks.

Generate
Context + query → Groq LLaMA → grounded answer

LLM instructed to answer ONLY from retrieved context. If no relevant chunks found — explicit "not found" message returned.

🤖 Feature 3 — Multi-Agent Research Pipeline

Research Agent
Tavily web search → structured summary

Calls Tavily API for top 5 web results. LLM synthesises a cited summary with <Research Summary> + <Sources Used> sections.

Critic Agent
Score on 4 axes → JSON verdict

Evaluates Accuracy, Completeness, Clarity, Source Usage (each /10). Returns structured JSON with scores, verdict (PASS/FAIL), strengths, weaknesses, feedback.

Pipeline Logic
FAIL + retry loop (max 2×)

If overall score < 7, the pipeline refines the original query using critic feedback and re-runs Research → Critic. Returns final result with attempt count.

agents/agent_pipeline.py while attempt < MAX_RETRIES: # MAX_RETRIES = 2 attempt += 1 research_result = run_research_agent(query) # Step 1 critic_result = run_critic_agent(research_result) # Step 2 if critic_result["passed"]: break # PASS ✅ # FAIL → refine query with critic feedback feedback = critic_result["critique"].get("feedback", "") query = f"{query}. Focus especially on: {feedback}"

Critic scoring schema (JSON): scores → {accuracy, completeness, clarity, source_usage}, overall_score (avg), verdict (PASS if ≥ 7), strengths[], weaknesses[], feedback (actionable improvement)

What Was Achieved

  • Full-stack production app — not a tutorial or notebook; a real, deployable application with clean separation of concerns
  • True multi-agent self-critique loop — the Critic Agent drives automatic quality improvement, not just a single LLM call
  • Real-time streaming — tokens arrive character-by-character in the React UI via SSE, just like ChatGPT
  • Zero-cost local embeddings — HuggingFace model runs locally, no per-token embedding API cost
  • Thread-safe memory — check_same_thread=False on SQLite connection handles FastAPI's concurrent request model
  • Mocked test suite — all 37 tests run without any real API keys using unittest.mock
  • Docker-ready — multi-stage build; entire system starts with docker compose up --build
